An agent can rewrite an export feature and still miss what a comma does to a supplier name.

Imagine a replacement that passes the demo: the file opens, the columns look right, and the code is clean. Then someone exports a name containing a comma, an empty field, or a record created before the last migration. The missing specification was in the old behavior.

Before asking for a rewrite, I want the agent to show which rule it has recovered and how it checked it.

[REA, Reverse Engineer Anything](https://github.com/morluto/rea), caught my attention because it supports that investigation. Its maintainers describe an MCP interface connecting agents to inspection tools for native binaries, JavaScript and Electron applications, websites, and other targets. Native analysis uses providers such as Hopper, Ghidra, or IDA.

I have reviewed the public documentation, not tested REA. What follows is the workflow I would try, not an evaluation of the tool.

## Ask one question the agent can check

“Understand this application” invites a convincing overview. “When does this exporter quote a field?” gives the agent a question it can investigate.

Start there. Then check empty values and whether the preview uses the same path as the saved file. Each question needs an observation that answers it. The agent does not need a complete theory of the application to explain one behavior well.

[REA’s public Calculator example](https://rea.tools/#calculator) follows a similarly narrow question: why does the percentage button behave differently after addition and multiplication? The site connects the explanation to inspected instructions and Microsoft’s source. It also labels the illustrative reasoning separately from the inspected material. That distinction matters: a readable explanation is not itself a captured observation.

## Test the competing explanation

Here is the investigation record I would want for a hypothetical CSV exporter.

Quoting every field remains possible until a plain-field probe distinguishes it from conditional quoting." caption="Original investigation sketch. Suppose the exporter turns `Acme, Inc.` into `"Acme, Inc."`. That fits at least two rules: quote every field, or quote fields containing delimiters. One output cannot distinguish them.

Try `Acme` next. The first rule predicts `"Acme"`; the second predicts `Acme`. Now the agent has a test that can eliminate one explanation. A name containing a quote needs another check.

The investigation record should keep the claim, its supporting input and output, and the next test together. If both explanations still fit, both stay open. A confident paragraph should not hide an unresolved question.

## Compare the replacement with the original

Recovering a rule does not prove the replacement follows it. The new exporter might quote a comma-containing name correctly in the preview and lose those quotes in the saved file.

Run the original and the replacement against the same test cases. Keep the input, both outputs, and any difference. Record the software version and any relevant time, locale, or stored state so the comparison can be repeated.

<Figure src="/writing/before-the-agent-rewrites-it/comparison.svg" alt="Shared synthetic fixtures feed an original exporter and a proposed replacement. Their outputs meet in a comparison table where a quoted-name mismatch blocks acceptance, while an untested locale remains unknown." caption="Proposed comparison workflow with illustrative outcomes. Passing these examples would not establish equivalence for every input." />

The quoted-name mismatch blocks acceptance. The untested locale stays unknown. A passing comparison supports the tested behavior; it does not establish that every input will match.

My first experiment would use a small application I maintain, or a public example intended for inspection. I would ask for one behavior, its supporting observations, competing explanations, and reproducible checks before asking for replacement code.

I would also check where the evidence goes. REA says analysis runs locally, but tool results reach the connected agent, whose model provider has its own data policy. Local inspection does not mean the whole workflow stays on the machine. [The project’s FAQ explains this distinction](https://github.com/morluto/rea#faq).

The handoff I want is an explanation I can test. Before the agent rewrites the exporter, it should show what happens to that comma and give me a check the replacement must pass.
